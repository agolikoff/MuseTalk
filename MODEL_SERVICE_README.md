# Сервис предзагрузки моделей MuseTalk

Этот сервис позволяет заранее загрузить все модели в память и выполнять инференс максимально быстро.

## Преимущества

- ✅ Модели загружаются один раз при старте
- ✅ Все модели остаются в памяти GPU/CPU
- ✅ Быстрая обработка запросов без повторной загрузки моделей
- ✅ Поддержка версий v1.0 и v1.5
- ✅ Поддержка режимов normal и realtime

## Использование

### Шаг 1: Запуск демон-сервиса (один раз)

Сначала нужно запустить демон-сервис, который загрузит модели в память:

```bash
# Запуск сервиса v1.5 в режиме normal на GPU 0
sh start_model_service.sh v1.5 normal 0

# Проверка, что сервис запущен
ps aux | grep model_daemon_service

# Проверка логов
tail -f ./logs/model_service_v1.5_normal_*.log
```

**Важно:** Сервис загружает модели один раз при старте и держит их в памяти. После запуска модели НЕ перезагружаются при каждом запросе.

### Шаг 2: Быстрый инференс (многократно)

После запуска сервиса можно отправлять запросы через `inference_fast.sh`:

```bash
# Для версии v1.5 в режиме normal
sh inference_fast.sh ./configs/inference/test.yaml v1.5 normal

# Для версии v1.0 в режиме realtime
sh inference_fast.sh ./configs/inference/realtime.yaml v1.0 realtime
```

**Преимущество:** Модели уже загружены в память, поэтому обработка начинается сразу без задержки на загрузку!

### Остановка сервиса

```bash
# Остановка сервиса
kill $(cat ./logs/model_service_v1.5_normal.pid)

# Или принудительная остановка
pkill -f model_daemon_service
```

### Прямое использование Python модуля

```bash
python3 -m scripts.model_loader_service \
    --version v1.5 \
    --gpu_id 0 \
    --use_float16 \
    --inference_config ./configs/inference/test.yaml \
    --result_dir ./results/test \
    --batch_size 8 \
    --fps 25 \
    --use_saved_coord
```

## Параметры

### Основные параметры

- `--version`: Версия модели (v1.0 или v1.5)
- `--gpu_id`: ID GPU для использования (по умолчанию 0)
- `--use_float16`: Использовать float16 для ускорения (рекомендуется)
- `--inference_config`: Путь к конфигу инференса (обязательно)
- `--result_dir`: Директория для сохранения результатов
- `--batch_size`: Размер батча (по умолчанию 8)
- `--fps`: FPS выходного видео (по умолчанию 25)
- `--use_saved_coord`: Использовать сохраненные координаты для ускорения

### Дополнительные параметры

- `--whisper_dir`: Путь к директории Whisper модели
- `--vae_type`: Тип VAE модели (по умолчанию sd-vae)
- `--ffmpeg_path`: Путь к ffmpeg
- `--left_cheek_width`: Ширина левой щеки для парсинга
- `--right_cheek_width`: Ширина правой щеки для парсинга
- `--extra_margin`: Дополнительный отступ для обрезки
- `--parsing_mode`: Режим парсинга лица (jaw, raw и т.д.)
- `--saved_coord`: Сохранить координаты для будущего использования

## Сравнение производительности

### Обычный инференс (inference.sh)
- Загрузка моделей: ~30-60 секунд **при каждом запуске**
- Обработка запроса: зависит от данных
- **Общее время**: загрузка + обработка **каждый раз**

### Быстрый инференс через демон (inference_fast.sh)
- Загрузка моделей: ~30-60 секунд **только один раз** при запуске демона
- Обработка запроса: только время обработки (модели уже в памяти!)
- **Общее время**: только обработка (без задержки на загрузку)

### Пример экономии времени

Если вы обрабатываете 10 запросов:
- **Обычный способ**: (30-60 сек загрузка + обработка) × 10 = **5-10 минут только на загрузку**
- **Демон-сервис**: 30-60 сек загрузка один раз + обработка × 10 = **экономия 4-9 минут!**

## Примеры конфигов

### test.yaml (normal mode)
```yaml
task_1:
  preparation: False
  video_path: "data/video/elon.mp4"
  audio_path: "data/audio/eng.wav"
  bbox_shift: 0

### realtime.yaml (realtime mode)

    audio_0: "data/audio/yongen.wav"

```

## Примечания

1. **Демон-сервис должен быть запущен перед использованием `inference_fast.sh`**
2. Модели загружаются один раз при старте демона и остаются в памяти
3. Используйте `use_saved_coord: true` в конфиге для ускорения при повторной обработке тех же видео
4. Для максимальной производительности используйте `--use_float16` (включено по умолчанию)
5. Убедитесь, что у вас достаточно памяти GPU для загрузки всех моделей
6. Логи сервиса сохраняются в директории `./logs/`
7. Запросы обрабатываются из директории `./requests/` и перемещаются в `./requests/processed/` после обработки
8. Можно отправлять несколько запросов одновременно - они будут обработаны последовательно

## Устранение неполадок

### Ошибка: "Модель не найдена"
Убедитесь, что модели загружены в правильные директории:
- v1.0: `./models/musetalk/`
- v1.5: `./models/musetalkV15/`

### Ошибка: "Out of memory"
Уменьшите `batch_size` или используйте CPU вместо GPU

### Сервис не останавливается
```bash
# Найти процесс
ps aux | grep model_loader_service

# Принудительная остановка
kill -9 <PID>
```

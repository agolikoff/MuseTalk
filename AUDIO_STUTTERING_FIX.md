# Исправление заикания аудио

## Проблема
Аудио заикается при воспроизведении через WebRTC.

## Важно: Какой трек используется?

**По умолчанию используется `DelayedMediaPlayerTrack`**, а не `SynchronizedAudioTrack`.

- **DelayedMediaPlayerTrack** (по умолчанию): Логи с префиксом `[DelayedMediaPlayerTrack]`
- **SynchronizedAudioTrack** (опционально): Логи с префиксом `[SynchronizedAudioTrack]`, включается через `USE_CUSTOM_AUDIO_TRACK=true`

Если в логах нет сообщений `SynchronizedAudioTrack`, значит используется `DelayedMediaPlayerTrack` - исправления применены к обоим трекам.

## Причины заикания

### 1. Неправильная синхронизация PTS
**Проблема**: PTS (Presentation Time Stamp) обновлялся на основе размера первого кадра, а не реального размера каждого кадра.

**Решение**: Теперь используется реальный размер каждого кадра для обновления PTS:
```python
actual_samples = original_frame.samples
self.audio_position += actual_samples  # Используем реальный размер
```

### 2. Использование оригинального кадра без копирования
**Проблема**: Оригинальный кадр использовался напрямую, что могло вызывать проблемы при повторном использовании.

**Решение**: Кадры теперь копируются перед отправкой:
```python
audio_data = original_frame.to_ndarray()
audio_frame.planes[0].update(audio_data.tobytes())
```

### 3. Неправильный начальный PTS
**Проблема**: Аудио начиналось с ненулевого PTS, что могло вызывать рассинхронизацию.

**Решение**: Аудио теперь начинается с нулевого PTS для плавного старта:
```python
self.audio_position = 0  # Начинаем с нуля
```

### 4. Разные размеры кадров
**Проблема**: Кадры могут иметь разный размер, что вызывает заикание.

**Решение**: Добавлена диагностика для обнаружения этой проблемы. При загрузке аудио проверяются размеры всех кадров:
```python
if min_samples != max_samples:
    print("⚠️ ВНИМАНИЕ: Размеры кадров различаются!")
```

## Внесенные изменения

### В классе `DelayedMediaPlayerTrack` (по умолчанию):

1. **Добавлено копирование кадров**: Кадры от MediaPlayer копируются перед отправкой
2. **Исправлен начальный PTS**: Счетчик тишины сброшен на 0 для плавного старта
3. **Добавлена диагностика**: Логирование размеров кадров, PTS и длительности

### В классе `SynchronizedAudioTrack` (опционально):

1. **Исправлен расчет PTS**: Используется реальный размер каждого кадра
2. **Добавлено копирование кадров**: Кадры копируются перед отправкой
3. **Исправлен начальный PTS**: Аудио начинается с нуля
4. **Добавлена диагностика**: Проверка размеров кадров при загрузке

### Улучшенная диагностика:

При загрузке аудио теперь выводится информация о размерах кадров:
```
[SynchronizedAudioTrack] ✓ Все кадры имеют одинаковый размер: 480 samples
```

Или предупреждение, если размеры различаются:
```
[SynchronizedAudioTrack] ⚠️ ВНИМАНИЕ: Размеры кадров различаются! min=240, max=960, avg=480.0
```

## Как проверить исправление

### Для DelayedMediaPlayerTrack (по умолчанию):

1. **Запустите трансляцию** и проверьте логи:
   ```
   [DelayedMediaPlayerTrack] recv вызван #1, audio_started=False
   [DelayedMediaPlayerTrack] ✓ Аудио синхронизировано с видео
   [DelayedMediaPlayerTrack] Получен кадр из MediaPlayer (samples=480, pts=..., duration=10.00ms)
   ```

2. **Проверьте размеры кадров**: В логах должны быть сообщения о размерах кадров (обычно 480 samples)

3. **Проверьте воспроизведение**: Аудио должно воспроизводиться плавно без заикания

### Для SynchronizedAudioTrack (если включен):

1. **Запустите трансляцию** и проверьте логи при загрузке аудио
2. **Проверьте размеры кадров**: Должно быть сообщение `✓ Все кадры имеют одинаковый размер: 480 samples`
3. **Проверьте воспроизведение**: Аудио должно воспроизводиться плавно без заикания

## Если проблема сохраняется

### Проверьте логи:
1. Есть ли предупреждение о разных размерах кадров?
2. Какие размеры кадров указаны в логах?

### Возможные дополнительные проблемы:

1. **Проблема с resampler**: Если размеры кадров различаются, возможно, нужно настроить resampler для создания кадров фиксированного размера

2. **Проблема с сетью**: Заикание может быть вызвано проблемами сети или WebRTC соединения

3. **Проблема с производительностью**: Если CPU перегружен, это может вызывать заикание

### Рекомендации:

- Если размеры кадров различаются, рассмотрите возможность использования resampler с фиксированным размером кадра
- Проверьте нагрузку на CPU/GPU
- Проверьте качество сетевого соединения
- Убедитесь, что аудио файл имеет правильный формат (48kHz, стерео, s16)

## Технические детали

### Формат аудио:
- **Sample rate**: 48000 Hz
- **Channels**: 2 (stereo)
- **Format**: s16 (16-bit signed integer)
- **Time base**: 1/48000

### Синхронизация с видео:
- Видео использует 90kHz timebase
- Аудио использует 48kHz timebase (sample_rate)
- PTS конвертируется между форматами при необходимости

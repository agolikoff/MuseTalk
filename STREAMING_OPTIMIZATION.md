# Оптимизация WebRTC стриминга

## Проблема
Трансляция тормозит из-за узких мест в обработке кадров.

## Внесенные оптимизации

### 1. Увеличен размер очереди кадров
- **Было**: 30 кадров
- **Стало**: 100 кадров
- **Эффект**: Лучшая буферизация при неравномерной генерации кадров

### 2. Добавлены метрики производительности
Система теперь автоматически логирует метрики каждые 5 секунд:
- **Размер очереди**: текущий размер и процент заполнения
- **Время конвертации кадров**: среднее, минимальное и максимальное время конвертации BGR→yuv420p
- **Время ожидания в очереди**: среднее и максимальное время ожидания кадров
- **Текущий FPS**: фактический FPS стрима (сравнивается с целевым)
- **Общее количество отправленных кадров**

### 3. Оптимизирована обработка переполнения очереди
- При переполнении очереди старые кадры автоматически удаляются (FIFO)
- Добавлены предупреждения при приближении к переполнению (90% заполнения)

### 4. Добавлен метод батчинга кадров
Новый метод `add_frames_batch()` позволяет добавлять несколько кадров за один вызов, что уменьшает накладные расходы.

## Как использовать для диагностики

### Просмотр метрик в логах
Метрики автоматически выводятся каждые 5 секунд в консоль:
```
[VideoStreamGenerator] 📊 МЕТРИКИ ПРОИЗВОДИТЕЛЬНОСТИ:
  - Очередь: 45/100 (45.0%)
  - Конвертация кадров: avg=12.34ms, min=8.21ms, max=25.67ms
  - Ожидание в очереди: avg=0.05ms, max=2.10ms
  - Текущий FPS: 24.8 (целевой: 25)
  - Всего кадров отправлено: 1245
```

### Анализ проблем

#### Проблема: Низкий FPS
**Признаки**: Текущий FPS значительно ниже целевого
**Возможные причины**:
- Медленная генерация кадров (проверьте логи модели)
- Медленная конвертация кадров (высокое среднее время конвертации)
- Переполнение очереди (очередь постоянно полная)

**Решения**:
- Увеличьте `batch_size` в модели для более быстрой генерации
- Уменьшите разрешение видео
- Проверьте нагрузку на CPU/GPU

#### Проблема: Высокое время конвертации
**Признаки**: Среднее время конвертации > 20ms
**Возможные причины**:
- Большое разрешение кадров
- Высокая нагрузка на CPU

**Решения**:
- Уменьшите разрешение видео (`video_width`, `video_height`)
- Используйте более мощный CPU
- Рассмотрите предварительную конвертацию кадров в отдельном потоке

#### Проблема: Переполнение очереди
**Признаки**: Очередь постоянно > 90%
**Возможные причины**:
- Генерация кадров быстрее, чем их отправка
- Медленная отправка через WebRTC

**Решения**:
- Увеличьте размер очереди (измените `maxsize` в `__init__`)
- Проверьте сетевые настройки WebRTC
- Уменьшите FPS целевого стрима

#### Проблема: Пустая очередь (задержки)
**Признаки**: Очередь часто пустая, высокое время ожидания
**Возможные причины**:
- Медленная генерация кадров
- Недостаточный batch_size

**Решения**:
- Увеличьте `batch_size` в параметрах генерации
- Проверьте производительность модели
- Уменьшите разрешение видео

## Использование батчинга кадров

Если вы модифицируете код генерации кадров, можно использовать батчинг:

```python
# Вместо:
for frame in frames:
    video_track.add_frame(frame)

# Используйте:
video_track.add_frames_batch(frames)
```

Это уменьшает количество вызовов `asyncio.run_coroutine_threadsafe` и может улучшить производительность.

## Дополнительные рекомендации

1. **Мониторинг**: Регулярно проверяйте метрики в логах для раннего обнаружения проблем
2. **Настройка очереди**: Размер очереди можно настроить в `VideoStreamGenerator.__init__()` (параметр `maxsize`)
3. **Разрешение**: Оптимальное разрешение зависит от вашего оборудования - экспериментируйте
4. **FPS**: Не устанавливайте FPS выше, чем может обеспечить генерация кадров

## Где смотреть логи

Все метрики и диагностическая информация выводятся в консоль с префиксом `[VideoStreamGenerator]`.

Для более детального анализа можно увеличить частоту логирования, изменив условие в методе `recv()`:
```python
if self.frame_count % 10 == 0:  # Вместо 30 - логировать каждые 10 кадров
```
